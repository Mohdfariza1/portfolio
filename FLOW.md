# How the Portfolio Site Works

Plain-words picture of the portfolio at **portfolio.bejaadigital.com**.
No code names. Anyone can read this.

---

## The Full Picture

```
   ┌──────────────┐                              ┌──────────────┐
   │   Farizal    │                              │   A client   │
   │ (the owner)  │                              │  or a lead   │
   └──────┬───────┘                              └──────┬───────┘
          │ edits the project list                      │ opens the link
          │ and the demo list                           │ Farizal sent
          ▼                                             ▼
   ┌─────────────────────────────────────────────────────────────┐
   │                   THE PORTFOLIO PAGE                        │
   │  One page that shows:                                       │
   │   • Past and current work, grouped by stage                 │
   │   • A gallery of demos the visitor can click through        │
   │   • Services, background, and a way to get in touch         │
   └───────────────┬──────────────────────────┬──────────────────┘
                   │                          │
                   │ opens a demo             │ taps "contact"
                   ▼                          ▼
        ┌────────────────────┐      ┌──────────────────────┐
        │  A WORKING DEMO    │      │  WhatsApp or email   │
        │  (own browser tab) │      │   opens, ready to    │
        │                    │      │       send           │
        └────────────────────┘      └──────────────────────┘

   Where it all lives:  a free web host (GitHub Pages) that serves the
   files as they are. There is no database and no server doing work.
```

**Worth knowing:** nothing is stored anywhere. The page has no sign-in,
collects nothing, and saves nothing about the visitor. The contact buttons
just open WhatsApp or the visitor's email app with the message pre-typed —
they never pretend to "send" anything.

## Workflow 1 — A client browses the work

```
  Client opens the link
          │
          ▼
  Sees the main page, with counts of
  finished, ongoing and upcoming work
          │
          ▼
  Picks a project from the list
          │
          ▼
  A panel opens with the details:
  what it is, what it does, the skills used
          │
          ├──► Taps "Visit project"  ──►  the live site opens
          │
          ├──► Taps "Try the mockup" ──►  the demo opens (see Workflow 2)
          │
          └──► Taps "Copy link"      ──►  a link to THIS project alone
                                           is copied, ready to paste
```

---

## Workflow 2 — A client tries the demos

```
  Client taps "Mockups" in the menu
          │
          ▼
  Sees every demo, grouped by the kind of job it is:
    Landing Pages · Business Websites · Booking & Catalogue
    Online Stores · Internal Systems · Dashboards & Automation
          │
          ▼
  Taps a category to narrow it down, or leaves it on "All"
          │
          ▼
  Taps a demo card
          │
          ▼
  The demo opens in a NEW TAB, so the portfolio stays open behind it
          │
          ▼
  Client clicks around a real working demo —
  books a slot, fills a basket, approves a leave request
          │
          ▼
  Closes the tab, back to the gallery where they left off
```

**Why the categories matter:** they are named after the kinds of job Farizal
sells. A client who wants a booking system can go straight to the booking
demos instead of being told about them.

## Workflow 3 — Farizal sends one project to one client

```
  Farizal opens the portfolio
          │
          ▼
  Opens the project he wants to show
          │
          ▼
  Taps "Share on WhatsApp" (or "Copy link")
          │
          ▼
  WhatsApp opens with the project name and its own link
          │
          ▼
  He picks the client and sends
          │
          ▼
  Client taps it and lands directly on THAT project,
  not on the front page
```

---

## Workflow 4 — Adding a new demo to the gallery

```
  Farizal (or Pitou) builds the demo as one self-contained page
          │
          ▼
  Puts it in its own folder inside the demos area
          │
          ▼
  Takes a picture of it for the gallery card
          │
          ▼
  Adds one short entry to the demo list:
  name, which category, what it does, what it was built with
          │
          ▼
  Pushes the change
          │
          ▼
  The live site rebuilds itself in about a minute.
  The counts, tabs and category headings all update on their own.
```

**Rule kept here:** every demo is a made-up business with made-up data.
No real client's figures, names or documents ever go into a demo.
Each demo carries a small "DEMO MOCKUP" badge so nobody mistakes it
for a live business.

## In plain words

The portfolio is a shop window. One side shows the real jobs Farizal has
done, and the other side lets a visitor walk in and try a working example
of the kind of thing they are thinking of buying — a booking page, an
online shop, a stock system — before they ever ask for a price.

Nothing is stored, nothing is submitted, and every link a client is given
takes them straight to the thing being talked about.
